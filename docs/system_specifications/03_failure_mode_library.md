## 1. FMEA 方法论

### 1.1 分析框架

每个失败模式包含以下要素：

| 要素 | 说明 |
|------|------|
| **失败模式** | 具体的失败表现 |
| **触发条件** | 导致失败的原因或场景 |
| **传播路径** | 失败如何在链路中传播 |
| **可观测信号** | 可用于检测的topic/统计量 |
| **保护策略** | 现有或建议的防护措施 |
| **严重度** | 1-10，越高越严重 |
| **发生频率** | 1-10，越高越频繁 |
| **检测难度** | 1-10，越高越难检测 |
| **RPN** | 风险优先数 = 严重度 × 发生频率 × 检测难度 |

### 1.2 链路传播模型

```
感知层 (LiDAR)
    │
    ├── 错检/漏检/错色 → 定位层
    │                       │
    │                       ├── 匹配错误 → 规划层
    │                       │                  │
    │                       │                  └── 路径异常 → 控制层
    │                       │                                  │
    │                       │                                  └── 执行错误
    │                       │
    │                       └── 定位跳变 → 规划层
    │
    └── 置信度异常 ─────────────────────────────────────────────→ 全链路
```

## 2. 感知层失败模式

### FMEA-P01: 锥桶漏检

| 项目 | 内容 |
|------|------|
| **失败模式** | 真实锥桶未被检测到 |
| **触发条件** | 远距离稀疏点云、遮挡、低反射率、地面分割参数不当 |
| **传播路径** | LiDAR → Location: 地图缺失锥桶 → Planning: 边界不完整 → Control: 出界风险 |
| **可观测信号** | `/perception/lidar_cluster/detections`: `confidence[]` 均值偏低、`len(points[])` 骤减；`/localization/cone_map`: `len(cone[])` 异常下降；topic_health: `detections` 频率下降 |
| **保护策略** | 缺锥插值Fallback (`missing_cone_fallback`)、历史帧预测 |
| **严重度** | 8 |
| **发生频率** | 5 |
| **检测难度** | 4 |
| **RPN** | 160 |

**代码位置**:
- 地面分割: `fast_ground_segmentation.cpp`
- 聚类: `lidar_cluster_core.cpp`
- 缺锥补偿: `location_mapper.cpp:581-615`

### 优先级排序说明

- **P0-安全 (SafetyCritical)**: 无论 RPN 高低，涉及人身安全/系统完整性的失败模式 **MUST** 单列为最高优先级。包括：紧急停车失效、TF 链断裂（全链路瘫痪）、时间不同步（全链路数据关联失效）、匹配丢失（定位完全失效）。
- **高优先级 (RPN ≥ 140)**: 需要立即关注和改进
- **中优先级 (RPN 60-139)**: 需要持续监控和优化
- **低优先级 (RPN < 60)**: 已有较好的保护机制

> **排序规则**: 先按 SafetyCritical 分组（安全关键项置顶），组内按严重度降序；非安全关键项按 RPN 降序。
